# Global Serie A player images

Issue: #36.

## Ownership

Player images are global Serie A data. The legacy `PlayerImagesJob` reads only global RealPlayers and Lega Serie A SDP metadata, so Fantazone keeps the replacement in the central `KeyserDSoze/Fantazone` repository. No `Fantazone.<group>` workflow, group PAT or group state is involved.

## Canonical static path

The Action writes provider images under:

```text
src/app/public/images/players/<legacy-player-key>.webp
```

Expo copies `public/` into the web export, so the canonical public URL is:

```text
https://fanta.plus/images/players/<legacy-player-key>.webp
```

A tracked neutral fallback is available at:

```text
src/app/public/images/players/default.webp
https://fanta.plus/images/players/default.webp
```

The frontend helper in `src/app/utils/playerImage.ts` uses those URLs and the same `getPlayerKey()` identity rule used by the persisted football domain.

## Why WebP instead of the legacy `.jpg` name

The original Azure job downloaded Lega Serie A SDP imagery whose payload/content type was WebP, but stored it with a `.jpg` object name. Fantazone does not preserve that misleading extension: ingestion validates the `RIFF....WEBP` magic bytes and stores the file as `.webp`.

This is a transport/static-asset correction, not a player identity or matching change. Player keys remain exact Fantasoccer keys: lowercase ASCII letters only. For example `Nicolò D'Ambrosio` becomes `nicoldambrosio`, because the accented `ò` is removed rather than transliterated.

## Preserved ingestion behavior

`ingest-player-images` preserves the useful legacy behavior:

- load canonical global RealPlayers for the internal Fantazone season;
- query Lega Serie A SDP seasons and require the current Fantazone season label;
- fetch all current-season player pages, up to the legacy safety limit of 100;
- append the previous-season catalog as image fallback;
- match normalized player name + role + team first, then name + role;
- prefer `_middle`, then `_celeb`, then the first non-empty imagery entry;
- never redownload an already tracked player image;
- isolate one image-download failure and continue with other players;
- when the season catalog is missing/unavailable, leave existing static files untouched.

Name normalization for provider matching remains the legacy HTML-decode/diacritic/apostrophe/whitespace normalization and is intentionally different from the persisted player-key algorithm.

## Action and configuration

The operation is exposed only by the central `.github/workflows/background-jobs.yml` as `ingest-player-images`.

Configurable repository variables:

```text
FANTAZONE_PLAYER_IMAGES_API_BASE_URL
FANTAZONE_PLAYER_IMAGES_MEDIA_BASE_URL
```

The central Action commits changes under `src/app/public/images/players` together with any canonical `data/**` output generated by the selected global job.

No automatic schedule is enabled yet. A real `workflow_dispatch` run against production RealPlayers + the current Lega Serie A catalog must succeed before scheduling is chosen and issue #36 is closed.
